## Formal run structure

- 24 task families x 3 conditions (N/P/C) x 2 instances = 144 paired tasks
- 3 methods (TMC-AE / R2 / R3) x 144 = 432 runs
- Organized as 48 matrix jobs (family x instance); each job restores the base
  fixture before every episode and runs its 9 episodes (3 conditions x 3
  methods) sequentially; `max-parallel: 20`
- Reward = 1 only if every ORM-evaluated reward condition holds; evaluated
  per run inside the restored fixture

## Known environment limitations (accepted, documented)

- v15 list views do not render rows on cold navigation in the headless setup;
  tasks that reference existing records carry deterministic routes instead.
- socket.io realtime is unavailable in the pwd.yml-derived stack (origin
  check fails); it does not affect form/list operations.

## Deviation policy

If a run cannot complete due to infrastructure (runner, network), it may be
re-dispatched with the same task/method. Any protocol-level change requires a
new amendment commit BEFORE the affected runs and a note in this file.
